# Версионирование проекта

Проект использует [Semantic Versioning](https://semver.org/lang/ru/) (SemVer) для управления версиями.

## Формат версии

Версия имеет формат: `MAJOR.MINOR.PATCH`

- **MAJOR** - увеличивается при несовместимых изменениях API
- **MINOR** - увеличивается при добавлении новой функциональности с обратной совместимостью
- **PATCH** - увеличивается при исправлении ошибок с обратной совместимостью

## Текущая версия

Текущая версия указана в:
- `package.json` - поле `version`
- `CHANGELOG.md` - последняя запись
- Отображается в приложении (правый нижний угол)

## Управление версиями

### Просмотр текущей версии

```bash
npm run version
```

### Обновление версии

#### Patch версия (1.0.0 → 1.0.1)
Для исправлений ошибок:
```bash
npm run version:patch
```

#### Minor версия (1.0.0 → 1.1.0)
Для новых функций с обратной совместимостью:
```bash
npm run version:minor
```

#### Major версия (1.0.0 → 2.0.0)
Для несовместимых изменений:
```bash
npm run version:major
```

### Создание релиза

Скрипт автоматически обновляет версию и создает git tag:

```bash
npm run release patch "Описание изменений"
npm run release minor "Добавлена новая функция"
npm run release major "Полная переработка API"
```

## Git теги

Каждая версия создает git tag в формате `v1.0.0`:

```bash
# Просмотр всех тегов
git tag

# Просмотр конкретного тега
git show v1.0.0

# Отправка тега на GitHub
git push origin v1.0.0

# Отправка всех тегов
git push origin --tags
```

## CHANGELOG.md

Все изменения документируются в `CHANGELOG.md`:

- **Добавлено** - новые функции
- **Изменено** - изменения в существующей функциональности
- **Устарело** - функции, которые скоро будут удалены
- **Удалено** - удаленные функции
- **Исправлено** - исправления ошибок
- **Безопасность** - исправления уязвимостей

## Примеры использования

### Исправление ошибки
```bash
# 1. Исправляем ошибку в коде
# 2. Обновляем версию
npm run version:patch
# 3. Обновляем CHANGELOG.md
# 4. Коммитим и пушим
git add .
git commit -m "fix: исправлена ошибка расчета"
git push origin stage
git push origin v1.0.1
```

### Добавление новой функции
```bash
# 1. Добавляем новую функцию
# 2. Обновляем версию
npm run version:minor
# 3. Обновляем CHANGELOG.md
# 4. Коммитим и пушим
git add .
git commit -m "feat: добавлена новая модель дивана"
git push origin stage
git push origin v1.1.0
```

### Использование release скрипта
```bash
# Автоматически обновит версию и создаст тег
npm run release patch "Исправлена ошибка в расчете стоимости"
```

## Отображение версии в приложении

Версия автоматически отображается в правом нижнем углу приложения через компонент `VersionBadge`.

Версия берется из `package.json` через переменную окружения `npm_package_version`.

## Рекомендации

1. **Всегда обновляйте CHANGELOG.md** при изменении версии
2. **Используйте осмысленные сообщения коммитов** с префиксами:
   - `feat:` - новая функция
   - `fix:` - исправление ошибки
   - `docs:` - изменения в документации
   - `style:` - форматирование кода
   - `refactor:` - рефакторинг
   - `test:` - добавление тестов
   - `chore:` - обновление зависимостей, версий и т.д.
3. **Создавайте теги для каждой версии** перед деплоем
4. **Публикуйте теги на GitHub** для отслеживания релизов
